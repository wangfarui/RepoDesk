# RepoDesk v0.1 当前实现与验证摘要

本文记录当前代码相对 `product-spec-v0.1.md`、`product-spec-v0.1-amendment.md` 和 `product-acceptance-stages-v0.1.md` 的实现状态。Workspace/Files、Git Review 与操作、Maven、`INT-01 Settings`、`INT-02`、`PERF-01`、`QA-01` 替代验证与 `REL-01` 均已通过用户验收。完整 Xcode 测试链路仍受环境阻塞。

## 已实现流程

- 原生打开、切换、关闭和恢复 Workspace；侧栏分开展示 Git 仓库和最近工作区。
- 登记、发现、重命名、置顶、排序、移除、重新定位和恢复 Workspace 内的嵌套 Git Repository。
- Workspace 上下文显示 Overview、Changes、Files、Maven；Repository 上下文显示 Changes、Files、History、Maven。
- Workspace 打开后自动后台加载全部已登记仓库的 Git Snapshot 和改动数，最多 4 个仓库并发；相同仓库刷新去重。
- Changes 在 Workspace 下支持全部或单仓库，在 Repository 下固定当前仓库；仅按 Changes/Unversioned Files 及 Directory/Module 展示，同一部分暂存文件只出现一次，并覆盖 rename、copy、conflict、binary 和 Java/Maven 常用文件图标。
- Changes 使用 HEAD 到当前工作区文件的 Unified/Side-by-side 单文件 Diff；History 仅针对当前 Repository，支持可搜索的 Branch/User 过滤、分页 Commit 和按 Directory/Module 独立组合分组的改动文件列表。普通 Commit 使用固定 Side-by-side Diff；Merge Commit 按 combined diff 展示同时不同于全部父提交的文件，两父 Merge 使用目标父提交/合并结果/来源父提交三栏 Diff。
- Repository Changes 支持按文件勾选 Commit 范围、Commit 信息、Commit 和 Commit And Push；Push 失败时保留已创建 Commit，并支持只重试 Push。Workspace 全仓库 Changes 保持审查模式，不允许跨仓库 Commit。
- Repository 顶部支持 Fetch、Pull、Push 和可搜索 Branch；支持本地/远程 Branch Checkout、tracking Branch 创建、Branch 比较、Push、Merge、Rename、安全 Delete，以及冲突文件编辑、Mark Resolved、Abort Merge 和 Continue Merge。
- Side-by-side Diff 支持左右两侧独立 Git Blame，展示已提交行的作者、日期和短 Hash，以及工作区新增行的未提交状态。
- Diff 隐藏原始 Git header，长代码行保持单行并支持水平滚动，同时支持忽略空白、折叠/展开未改动片段和 Jump To Source；后台刷新保留现有内容并原子替换，不显示转圈或旧文件 Diff。
- Files 懒加载 Workspace 或当前 Repository 文件树，支持单子目录紧凑显示、隐藏文件、双击 Shift 的文件名搜索、`Command+Shift+F` 全文检索、文本编辑、长源码行不换行与水平滚动、安全保存、外部冲突保护和 Markdown 块级预览。
- Workspace Maven 支持 Maven Home、JDK/JAVA_HOME、User settings file、Local repository、Profiles、`-am`、附加参数和运行记录策略持久化；路径校验成功显示版本或有效状态，保存失败会明确提示。
- 原生 Settings 窗口可通过 `Command+,` 或主窗口齿轮打开，以固定侧栏集中提供通用刷新、Files、Diff 和当前 Workspace Maven 配置；应用级偏好持久化并立即驱动文件监听、前台刷新、文件树、Markdown 默认视图和后续 Changes Diff。通用页展示当前 Workspace、版本 `0.1.0` 与 Bundle ID。
- Repository Maven 自动扫描多模块 POM，展示 Lifecycle clean、compile、package、install、deploy；运行前展示最终 executable、参数数组、环境和工作目录，deploy 使用同一命令二次确认，实时输出可复制和清除。
- Maven Stop 终止整个独立进程组，先 `SIGTERM`，2 秒后仍存活则 `SIGKILL`；最近运行按 Workspace 保存并按 Repository 展示，支持历史日志、删除、模块有效性提示和按原最终命令重跑。
- Maven 实时输出位于底部时自动跟随新增内容；用户向上滚动后暂停并显示快速跳转按钮，回到底部后自动恢复跟随。输出块先合并为单个待处理 UI flush，同一次运行只增量追加新增文本，切换历史或清空时再完整替换。
- `pom.xml`、`mvnw`、`mvnw.cmd` 变化会触发对应 Repository 的 Maven 项目异步重扫；普通源码事件不会触发，旧模块树保留到新结果原子替换。
- History 分栏尺寸按 Workspace 保存；切换 Commit 时保留旧内容直至新内容准备完成，避免闪烁和布局收缩。
- Workspace 恢复同时覆盖导航上下文、页面、文件和 Markdown 模式、Workspace Changes 当前仓库/文件、History Branch/User/Commit/文件与分栏、Maven 模块/Goal/最近运行选择；旧窗口状态自动使用兼容默认值。
- 顶部页面支持按当前顺序使用 `Command+1...4` 切换，`Command+R` 统一刷新；Workspace 或 Repository 失效时主内容区直接提供重新选择、重新定位或返回 Workspace 的入口。
- Workspace 使用递归 FSEvents、0.3 秒合并防抖和精确路径匹配；每批事件路径只标准化一次，只刷新实际受影响的目录及 Repository，并提供可轮转的诊断日志。

## 安全约束

- 自动 Git Snapshot 和文件事件刷新只执行读取；Commit、Fetch/Pull/Push、Checkout、Merge、Rename、安全 Delete 和冲突解决只在用户明确操作后针对单个 Repository 执行。
- v0.1 不提供 Reset、Rebase、force Push、任意 Git 命令或自动 Git 写入。
- Git 参数和 Maven/任务参数始终使用数组传递，不通过 Shell 字符串拼接；Git 远程操作禁用终端交互提示，Commit 信息不会出现在界面错误详情中。
- Commit And Push 明确区分两个阶段；Push 失败不会回滚或重复创建已经成功的 Commit。
- Git 读取命令具有 10 秒超时，Git 写入/远程操作具有 120 秒上限，取消会终止当前命令；Maven/Java 使用独立进程组完成温和停止和超时强制清理。
- Maven 历史只持久化 RepoDesk 显式配置的 `JAVA_HOME`，不会把完整进程环境中的 Token 或凭据写入运行记录。
- Repository 移除只删除 RepoDesk 登记，不删除磁盘目录。
- 文件保存保持原子写入、编码和权限，并执行版本检查；外部变化不会被静默覆盖。
- 二进制文件不可编辑，超过 1 MB 使用只读模式，超过 10 MB 不载入编辑器。
- deploy 必须确认；应用不包含账号、遥测、云同步、LSP、Java 索引或 Debugger，也不包含 Reset、Rebase、force Push、任意/自动 Git 写操作。

## 最近验证

- 最终 `REL-01` 回归通过 Swift 严格并发类型检查、测试源码解析、Settings 持久化与四页签渲染、跨模块状态恢复、深浅色常见窗口渲染、统一性能门槛、Markdown、Git、Maven、命令取消、进程组清理、本地 App 构建、版本/图标检查和 ad-hoc 签名验证。当前受限沙箱拒绝启动 FSEvents 流；同一真实 FSEvents 夹具已在前一阶段宿主权限下通过，监控实现本轮未改动。
- Git 操作测试覆盖选中文件 Commit、真实临时仓库 Commit、Commit And Push 分阶段状态、Push 失败后单独重试、Fetch 后历史刷新、远程 tracking Branch Checkout，以及 Blame 的已提交/未提交行解析和布局性能。
- QA 集成夹具 `scripts/verify-qa-integration.swift` 进一步覆盖真实 Git Commit、工作区/提交 Blame、远程 tracking Branch、冲突文件显式解决与 Continue Merge，以及 UserDefaults 窗口状态和 AppState 恢复。
- 统一性能夹具实测：仓库发现 0.047 秒、文件树 0.040 秒、文件搜索 0.051 秒、Git Snapshot 解析 0.025 秒、1 万项 Changes 规划 0.351 秒、Diff 0.023 秒、1 万行 Blame 0.250 秒、5 千条 History 0.228 秒、1 千文件 Git 操作规划 0.004 秒。
- 2 万行 Maven 日志的 300 次增量渲染为 0.011 秒，1 万输出块合并为一次待处理 UI flush；1 万文件事件、500 个已加载目录的刷新规划约 0.185 秒。连续 200 批 Agent 写入保持每批只命中所属 Repository，Workspace 根文件不会误刷新全部嵌套 Repository。
- 真实 `pangmaoyun` 启动后约 1 秒自动加载 23 个 Repository，稳定后 RepoDesk 为 `0.0% CPU / 0.3% MEM`。
- 缓存 Snapshot 刷新不进入可见加载状态；失败保留旧列表，选中 Diff 在后台静默更新。
- Git Snapshot 初次失败使用 250ms、1s 有限退避重试，最多调用三次；重试等待不占用四仓库并发槽，取消、仓库移除或 Workspace 切换会丢弃后续结果。
- 最新应用稳定状态为 `0.0% CPU / 0.7% MEM`；诊断日志显示 23 个 Repository Snapshot 正常完成，无超时或刷新错误。
